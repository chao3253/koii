# Koii 运维手册（自建后端）

> 这份手册放在你自己手里。即使换电脑、换对话、换 AI，照着它也能把系统维护好。
> 建议：复制一份到密码管理器；服务器上也留一份：`/opt/koii-运维手册.md`。

---

## 一、系统长什么样

- **前端**：`https://cz520.online`，静态文件托管在 GitHub Pages（仓库 `chao3253/koii` 的 `gh-pages` 分支）
- **后端**：`https://api.cz520.online`，跑在腾讯云香港轻量服务器上（Docker + Supabase 全家桶）
- **数据**：PostgreSQL（文字 + 登录账号）+ 私有存储桶 `koii-photos`（照片）
- **证书**：Let's Encrypt，certbot 自动续期

```
浏览器
  ├─ cz520.online        → GitHub Pages（界面）
  └─ api.cz520.online    → 你的服务器
                              └─ Nginx（HTTPS）
                                   └─ Supabase 网关
                                        ├─ 登录 Auth
                                        ├─ 数据库 Postgres
                                        ├─ 照片 Storage
                                        └─ 实时 Realtime
```

## 二、账号与钥匙清单

| 用途 | 在哪里 | 备注 |
|---|---|---|
| 服务器 | 腾讯云控制台 | 到期时间、续费、防火墙 |
| 域名 / DNS | 阿里云域名控制台 | `cz520.online`、`api` 的 A 记录 |
| 前端代码 | GitHub `chao3253/koii` | `gh-pages` 分支 |
| 服务器登录 | `ssh ubuntu@<服务器IP>` | 你平时登录的账号；密码/密钥存密码管理器 |
| 后端密钥 | 服务器 `/opt/supabase/docker/.env` | **绝密**，不要发给任何人 |
| 后台 Studio | SSH 隧道后访问 `http://localhost:8000` | 账号密码在 `.env` 的 `DASHBOARD_*` |
| 网站登录 | 新站邮箱 + 密码 | 两人共用 |

> ⚠️ `SERVICE_ROLE_KEY` 是万能钥匙，只留在 `.env`；前端只用 `ANON_KEY`（公开无妨）。

## 三、日常命令

登录服务器：

```bash
ssh ubuntu@<服务器IP>
```

进入部署目录：

```bash
cd /opt/supabase/docker
```

看所有容器状态：

```bash
sudo docker compose ps
```

重启全部 / 单个：

```bash
sudo docker compose up -d
sudo docker compose restart auth
```

看日志（最后 100 行）：

```bash
sudo docker compose logs --tail=100 auth
```

看资源：

```bash
free -h
df -h
sudo docker system df
```

健康检查：

```bash
curl -s -H "apikey: $(grep '^ANON_KEY=' /opt/supabase/docker/.env | cut -d= -f2-)" https://api.cz520.online/auth/v1/health
```

返回 JSON（含 `"name":"GoTrue"`）即正常。

## 四、备份

手动备份：

```bash
sudo /opt/backup/backup.sh
ls -lh /opt/backup
```

每天凌晨 3:17 自动备份（root 的 crontab）：

```bash
sudo crontab -l
```

备份内容：

- `db-YYYY-MM-DD.sql.gz`：数据库（文字 + 登录账号 + 照片索引）
- `storage-YYYY-MM-DD.tar.gz`：照片文件
- `env-YYYY-MM-DD.bak`：密钥配置（绝密，权限 600，查看要加 `sudo`）
- 自动保留最近 7 天

正常时 `/opt/backup` 里应有 4 个文件（`backup.sh` + 上面三个）。看最近一次自动备份的结果：

```bash
sudo tail -20 /var/log/koii-backup.log
```

恢复演练（**只恢复到临时库，不动生产库**）：

```bash
cd /opt/supabase/docker
sudo docker compose exec -T db createdb -U postgres koii_restore_test
gunzip -c /opt/backup/db-YYYY-MM-DD.sql.gz | sudo docker compose exec -T db psql -U postgres -d koii_restore_test
sudo docker compose exec -T db psql -U postgres -d koii_restore_test -c "select count(*) from auth.users;"
sudo docker compose exec -T db dropdb -U postgres koii_restore_test
```

能查到用户数，说明备份是活的。中途有一些 `already exists` 之类的提示可以忽略。

> 没恢复过的备份只能叫「文件」。建议每月演练一次。

## 六、常见故障排查

**顺序：日志 → 状态 → 资源 → 网络**

```bash
cd /opt/supabase/docker
sudo docker compose logs --tail=100 <服务名>
sudo docker compose ps
free -h && df -h
curl -s http://127.0.0.1:8000/auth/v1/health
```

| 现象 | 先看什么 |
|---|---|
| 网站打不开 | GitHub Pages 状态、DNS、浏览器控制台 |
| 能打开但登录失败 | `api.cz520.online` 证书、`docker compose ps`、auth 日志 |
| 照片裂图 | storage 容器、磁盘空间、照片路径前缀 |
| 实时不同步 | Nginx 的 WebSocket 头、realtime 容器日志 |
| 容器反复重启 | `free -h` 看内存；`docker compose logs` 看原因 |
| 磁盘满 | `df -h`、`docker system df`，清理旧镜像/备份 |
| 证书过期 | `sudo certbot renew`，检查 80 端口是否放行 |

把报错**原文**贴给 AI，比描述「打不开」有用一百倍。

## 八、安全习惯

- 云防火墙 + ufw 只开 `22 / 80 / 443`
- 不把 `.env`、`SERVICE_ROLE_KEY`、服务器密码发给任何人
- 定期更新系统：

  ```bash
  sudo apt update && sudo apt upgrade -y
  ```

- 注册已关闭（`DISABLE_SIGNUP=true`），只保留你们的账号。验证方法：

  ```bash
  sudo grep '^DISABLE_SIGNUP=' /opt/supabase/docker/.env
  cd /opt/supabase/docker && sudo docker compose exec -T auth printenv GOTRUE_DISABLE_SIGNUP
  ```

  两处都应是 `true`；再调一次注册接口应返回 `422 signup_disabled`。
- 建议最终改成 SSH 密钥登录，关闭密码登录

## 九、费用

- 服务器按月/年续费，到期前会有提醒
- 控制台设「费用预警」（例如每月 ¥120）
- 轻量服务器有月流量包，照片看得多时留意
- 续费前比价：年付折扣 / 活动价 / 是否降配

## 十、回滚方案

旧托管 Supabase **先不要删**。若新站出现严重问题：

1. 把 `src/config.ts` 改回旧 URL + 旧 anon key
2. 重新构建并发布
3. 数据以旧站为准

确认新站稳定运行 1～2 周后，再停用旧站。
